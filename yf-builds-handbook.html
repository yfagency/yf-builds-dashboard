YF Builds Handbook

Everything the team builds with Claude — mock-ups, pages, prototypes, small apps — in one place, with the latest version always one click away.

Two things to know

Everyone

Open the dashboard

It's a link. Search, filter, download the latest version of anything the team has made. You never need to open Notion or GitHub.

Anyone who builds

Say one sentence

“log this build” in Claude Code. That's the whole publishing process — no git, no repo settings, no forms.

First time only

  1. Open the dashboard link and bookmark it

    ZF will send it to you. It opens in the browser, no install.

  2. Connect Notion to your Claude account, once

    The dashboard reads the build list using your Notion connection, not a shared one — which is why nobody can see anything you couldn't already see. Go to claude.ai → Settings → Connectors and add Notion, signing in with your YF workspace. If the dashboard tells you to add or reconnect Notion, this is the fix.

  3. That's it, if you only need to download things

    Everything below is for people who want to publish their own builds.

Publishing your own build

You need Claude Code on your machine, the GitHub CLI signed in, and the publishing skill installed. The skill is self-serve — two lines in Claude Code, once, and you never think about it again:

/plugin marketplace add https://github.com/yfagency/yf-claude-plugins.git

/plugin install yf-builds@yf-tools

Ask ZF only for two things: access to the yfagency org, and gh auth login if you've never set up the GitHub CLI (winget install GitHub.cli on Windows, brew install gh on a Mac).

  1. Finish the thing, in its own folder

    One folder per build, containing only what should ship — no scratch files, no notes, no .env.

  2. Open Claude Code in that folder and say it

    “log this build”that's the entire interface

    It asks what to call it and which client it's for, if it can't work that out from what you've been doing. Then it creates the repo, pushes the files and registers the build.

  3. It gives you two links

    The repo, and the download URL. You can forward the download URL to anyone.

Builds are public

That's deliberate — it's what lets anyone download one without a GitHub account. So nothing secret goes in a build: no API keys, no credentials, no client data, nothing under NDA. If a build genuinely can't be public, stop and talk to ZF; it needs a different home.

Updating a build you already published

Exactly the same sentence.

“log this build”said again, in the same folder

It notices the build already exists and adds a new version instead of creating a second entry. Everyone downloading gets the new one immediately; every earlier version stays recoverable under GitHub & history.

Changing the status, version label, notes or client is a different job, and it happens on the dashboard: press Edit on the card, change it, save. It's yours to maintain — a build that says In Progress six months after you finished it is only misleading because nobody pressed that button.

One thing you can't edit

The commit line — the dot, the date, the author. That's read from git by the nightly sync, so it always reflects what actually happened rather than what anyone typed. If a build looks stale, the fix is to work on it, not to edit it.

When something looks wrong

What you seeWhat it means
My build isn't on the dashboard Nine times out of ten the repo description is missing its [YF Build] prefix, which is how builds are told apart from YF's other repos. Otherwise: new builds appear at the 06:30 JST sync, so something published this afternoon shows up tomorrow morning. ZF can force it sooner.
“Add Notion in Settings → Connectors” Your Claude account has no Notion connection yet. Step 2 of First time only.
“Reconnect Notion” Your connection expired — normal, occasional. Reconnect in the same place and reload.
“Choose which Notion to use” You have more than one Notion connection. Pick the YF workspace.
The commit line says Not synced yet The build is registered but the sync hasn't read its repo yet. It fills in overnight.
Download gives me a 404 The repo was renamed, deleted or made private. Tell ZF — private repos are invisible to the dashboard by design.

Three rules

  • One repo per build. Don't add a second build to an existing one — Download-latest would hand people the wrong thing.
  • Nothing secret in a build. Public is what makes downloads work for everyone.
  • Publishing happens in Claude Code. Not in Cowork — Cowork can read GitHub but can't push to it, which is a limit of its sandbox rather than a setting anyone can change.

Maintained by ZF. The dashboard is the only interface — if something here sends you to Notion or GitHub to get ordinary work done, that's a gap worth reporting rather than a habit worth forming.
