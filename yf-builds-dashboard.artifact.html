Three rules

Everything else here is help. These three are the ones that break something if you get them wrong.

  • One repo per build. Don't add a second build to an existing one — Download latest would hand people the wrong thing.
  • Nothing secret in a build. Public is what makes downloads work for everyone, including people outside YF. That covers claims as well as credentials: naming a client on a page makes it a public statement.
  • Publishing happens in Claude Code. Not in Cowork, which can read GitHub but can't push to it.
  • Every build has a thumbnail. A gallery of grey rectangles is useless, so a card with no picture shows a striped Thumbnail missing tile and gets counted at the top of the page until it's fixed. If your build runs in a browser this is automatic; if it doesn't, Claude asks you for an image when you publish.

Start here

This is the registry of everything the team builds with Claude — mock-ups, pages, prototypes, small apps. It answers three questions: what have we built, who built it, and how do I get the latest version.

If you only want to look at things and download them, you're already done. Search, filter, press Download latest on anything.

One-time setup, if the page ever tells you to. This dashboard reads the registry using your Notion connection, not a shared one — which is why nobody can see anything here they couldn't already see. If you get a message about adding or reconnecting Notion, go to claude.ai → Settings → Connectors and add Notion, signed into the YF workspace. That's the fix, every time.

Nothing to install for publishing either. The skill that publishes builds is shared across the team, so it's already in your Claude Code. You need the GitHub CLI signed in once — see Publishing.

Starting a session in Claude Code

The desktop app has three tabs and only one of them is the right place for this. Chat can't see your files. Cowork works in a sandbox that can't push to GitHub. Use Code.

  1. Open the Code tab and choose Local

    Not Cloud. A cloud session clones a GitHub repo rather than reading your machine, so it can't see the thing you just made — and its git credentials are scoped by a proxy, so it can't create a repo either. Local runs on your own files with your own login, which is the whole reason publishing works here and not in Cowork.

  2. Select the folder your build is in

    Not a GitHub repo, and not some shared folder — the folder containing what you made. The repo doesn't exist yet; publishing creates it. Keep builds at Documents/YF Builds/<build-name>/, one folder each, and this question stops coming up.

  3. Set the permission mode to Auto

    Publishing runs a handful of git and GitHub commands. In Manual mode you'll be asked to approve each one, which is a lot of clicking to say yes to. Plan is worth knowing about separately: it thinks through an approach without touching files, which is the right mode before anything large.

  4. Say what you want, in plain language

    “Build me a one-page microsite for the TDK town hall”. It writes the files in that folder; the Browser pane previews them as it goes, so you can look at the thing rather than read about it. Type / to see the skills available to you.

  5. When you like it, say “push this build”

    That's the handover to Publishing. Everything from there is automatic.

Windows only, once: local sessions need Git for Windows installed. It's the one thing that has to exist before Claude can set the rest up itself. Macs already have it.

Publishing your own build

Publishing happens in Claude Code, on your own machine. It can't happen in Cowork: that sandbox can read GitHub but not push to it, which is a limit of the sandbox rather than a setting anyone can change.

“push this build”

Said in Claude Code, in the folder containing the thing you made. It creates the repo, pushes the files, turns on hosting, and registers the card. It asks what to call it and which client it's for only if that isn't obvious from what you've been doing.

Never done this before? Say it anyway. There's no setup for you to do first. If your machine is missing anything — the GitHub CLI, a login, a git identity — Claude installs and configures it as part of the same request. The only moment it needs you is approving a GitHub login in your browser, and it will tell you exactly what to click.

The one thing it can't do for you is put you in the yfagency organisation. If you're not in it yet, it stops and says so — then it's one line for ZF and you try again.

One folder per build, containing only what should ship — no scratch files, no notes, no .env.

Builds are public

That's what lets anyone download one without a GitHub account. So: no API keys, no credentials, no client data, nothing under NDA. Watch for claims as well as secrets — a page that names clients or carries positioning copy becomes a public statement the moment it goes live. If a build genuinely can't be public, stop and talk to ZF; it needs a different home.

Updating a build you already published

Name the build you mean:

“update this build — Work Mosaic”

Use the name as it appears on its card. Naming it is what makes this unambiguous: Claude finds that build in the registry, checks you're pointing at the right repo, and adds a version rather than creating a second entry. Everyone downloading gets the new one immediately, and every earlier version stays recoverable under GitHub & history.

If somebody else has the build checked out, it tells you who and since when before pushing over their work.

The commit line and the freshness dot catch up at the next sync rather than instantly — see How current is this.

Editing what a card says

Press Edit on any card — yours or anyone's. Status, version, notes, client, live URL, tech stack, repo and branch are all yours to change, and they save straight back to the registry. You never need to open Notion; that's the whole point of this page.

Add build in the top right registers a card by hand without publishing anything — useful for something hosted elsewhere. Most people should ignore it.

One thing you can't edit

The commit line: the dot, the date, the author. That comes from git, so it always says what actually happened rather than what anyone typed. If a build looks stale, the fix is to work on it, not to edit it.

Archiving and status

One build: the status badge on the card is the control. Click it, pick a status, done — it saves as you pick. Set it to Archived and the build drops out of the gallery.

Several at once: tick Select in the bar at the top, tick the cards you mean, choose a status and press Apply. Worth it for a clear-out; overkill for one card.

Archived builds are hidden, never deleted. Tick Show archived to see them and set them back to anything. The repo, the download and the live URL all keep working either way — archiving is about what the team looks at, not about what exists.

Checking a build out

Optional, and only useful when more than one person might touch the same build. Press Check out on a card and it shows your name to everyone else looking at the dashboard, so nobody starts editing the same thing in parallel. Press Check in when you're done.

The first time you check something out it asks for your name or initials and remembers them in this browser. Nothing else is stored about you.

It's a note, not a lock. Anyone can still publish, and anyone can check a build in on someone's behalf — the button says so when it isn't yours. A lock nobody can break causes worse problems than a claim everybody can see, especially at 3pm on a Friday when the person who has it is asleep in another timezone.

Claude reads it too: when you publish an update to a build somebody else has checked out, it tells you before pushing.

What you seeWhat it means
My build isn't hereAlmost always the repo description is missing its [YF Build] prefix, which is how builds are told apart from YF's other repos. Otherwise: new builds appear at the 06:30 JST sync, so something published this afternoon shows up tomorrow morning. ZF can force it sooner.
“Add Notion in Settings → Connectors”Your Claude account has no Notion connection yet. See Start here.
“Reconnect Notion”Your connection expired. Normal, occasional. Reconnect and reload.
“Choose which Notion to use”You have more than one Notion connection. Pick the YF workspace.
The commit line says Not synced yetThe build is registered but the sync hasn't read its repo yet. It fills in overnight.
A button does nothingSome browsers won't let this page open a new tab. Use Links on the card and copy the URL instead.
Download gives a 404The repo was renamed, deleted, or made private. Tell ZF — private repos are invisible here by design.
A thumbnail is a grey placeholderThe build has no live version, or the dashboard hasn't been republished since it was added. Harmless.
