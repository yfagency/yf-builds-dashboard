Builds live in the YF Builds registry and the files live in public GitHub repos under yfagency. This page reads both through your own Notion connector — nothing is stored in the page. Commit, author and date are filled in by the daily 06:30 JST sync.

Adding a build

Publishing happens in Claude Code. Everything else happens here.

“log this build” — said in Claude Code

It creates the GitHub repo, pushes the files, and registers the build. It asks what to call it and which client it's for if that isn't obvious from what you were working on.

Why Claude Code and not here? Cowork can read GitHub but cannot push to it — a hard limit of its sandbox, not a setting anyone can change. Claude Code runs on your own machine with your own GitHub login, so it can.

Get the skill. Ask ZF for yf-builds-publish. Once it's installed, the sentence above is the whole interface — no git commands, no repo settings.

Updating something that already exists is identical. Say the same thing; it notices the build is already published and adds a version. Every earlier version stays recoverable.

Nothing secret in a build. Builds are public, which is what makes Download latest work for anyone you send it to. No API keys, no client data, no credentials.

A new build appears here after the next morning sync, or right away if you say “sync the builds” in Cowork. That same sync fills in the commit line on each card.

Add build registers a card by hand without publishing anything — useful for something hosted elsewhere. Most people should ignore it.
